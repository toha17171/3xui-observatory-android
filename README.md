# 3x-ui Observatory для Android

Нативное Android-приложение и виджет домашнего экрана для наблюдения за outbound из вкладки **Xray Observatory** панели [3x-ui](https://github.com/MHSanaei/3x-ui).

## Возможности v1.0

- Дашборд: имена outbound, доступность (alive), задержка (delay, мс), время последнего обновления.
- Виджет (начальный размер ~4×3) показывает до 4 outbound, в первую очередь недоступные; тап по виджету открывает приложение, кнопка ↻ обновляет данные.
- **Настройки внутри приложения**: несколько серверов (добавление, выбор, удаление), название, HTTPS URL панели, токен API, тест подключения, интервал проверки 15/30/60 минут, тёмная тема, уведомления об отказах и восстановлении.
- Изолированные сохранённые данные по каждому серверу, отображение последнего успешного снимка при сбое подключения.
- Авторизация через API-токен с областью `monitor`. Токены хранятся зашифрованными ключом Android Keystore (AES-GCM), не сохраняются в исходниках и не попадают в резервные копии Android.
- Режим только чтения. Приложение не управляет Xray и не открывает административные методы API.

## Сборка APK (Android Studio)

1. Установите Android Studio с Android SDK Platform 35, Build Tools 35.0.0 и JDK 21.
2. Откройте каталог проекта (`File → Open`). При необходимости выберите Gradle 8.9 в настройках Gradle.
3. `Build → Build APK(s)` или в терминале с установленным Gradle 8.9: `gradle assembleDebug`.
4. Файл: `app/build/outputs/apk/debug/app-debug.apk`.
5. **Автосборка на GitHub:** после загрузки файлов в репозиторий запустите `Actions → Android APK → Run workflow`. Готовый debug APK появится в `Artifacts` этого workflow.

> Проект намеренно не содержит Gradle Wrapper JAR: CI использует `gradle/actions/setup-gradle` версии 8.9. При локальном запуске из CLI установите Gradle 8.9; Android Studio сможет предложить настройку Gradle при импорте.

## Настройка 3x-ui

1. На панели 3x-ui настройте **Observatory**, включите в шаблоне конфигурации Xray блок `metrics`, иначе ответ API будет пустым.
2. В разделе `Settings → Security → API Token` создайте токен со scope `monitor`.
3. В приложении: `Настройки → Добавить сервер`, введите имя, HTTPS-адрес панели (включая нестандартный базовый путь, например `https://example.org/custom-base/`) и токен.
4. Нажмите **Проверить подключение**, затем **Сохранить подключение**.
5. На домашнем экране Android добавьте виджет **3x-ui Observatory**.

Адрес формируется как `<base-url>/panel/api/server/xrayObservatory`, например:

```
curl -H 'Authorization: Bearer YOUR_READONLY_TOKEN' \
  'https://example.org/custom-base/panel/api/server/xrayObservatory'
```

Пример ожидаемого ответа:

```json
{"success":true,"obj":[{"tag":"de-fra","alive":true,"delay":42,"lastSeenTime":1794350000,"lastTryTime":1794350000,"updatedAt":1794350002}]}
```

## Важные ограничения

- Android JobScheduler не гарантирует обновление строго каждые 15/30/60 минут; энергосбережение может задерживать проверки. Кнопка ↻ делает запрос сразу. Уведомления о восстановлении/отказе появляются **только после обнаружения перехода статуса между двумя успешными проверками**, а не немедленно в момент сбоя.
- Если HTTPS сертификат недоверенный, соединение будет отклонено; отключать проверку TLS не рекомендуется.
- Для Android 13+ требуется разрешение на уведомления, если опция включена.
- В v1.0 все экземпляры виджета показывают **выбранный в приложении** профиль и до 4 узлов.
- Нет гарантии работы со старыми версиями 3x-ui без API `/panel/api/server/xrayObservatory`.
- Нельзя восстановить зашифрованный токен после сброса данных приложения или утраты ключа Keystore; введите новый токен.

## Технологии

Java 17, Android SDK (min 26, target 35), Android JobScheduler, AppWidgetProvider/RemoteViews, Android Keystore, HttpURLConnection, JSON. Сторонних Java/Kotlin библиотек нет.

## Распространение

Это независимый клиент 3x-ui, неофициальный продукт. Исходный код приложения доступен для использования и доработки; у стороннего проекта 3x-ui действует его собственная лицензия.

## Создание приватного GitHub-репозитория и автоматическая сборка одной командой

Подключён GitHub-аккаунт `toha17171`; скрипты создают в нём **приватный** репозиторий `3xui-observatory-android`, загружают исходники, дожидаются GitHub Actions и сохраняют APK в `apk/app-debug.apk`.

**Windows** (установить Git и [GitHub CLI](https://cli.github.com/), один раз выполнить `gh auth login`):

```powershell
powershell -ExecutionPolicy Bypass -File .\publish_github.ps1
```

**Linux/macOS** (Git + GitHub CLI):

```bash
./publish_github.sh
```

Если репозиторий уже существует, скрипт отправляет текущую ветку в его `main`. Не запускайте скрипт из другого проекта.
