# 3x-ui Observatory — Android v1.2.0

Неофициальное Android-приложение с нативными виджетами для [3x-ui](https://github.com/MHSanaei/3x-ui). Android 8.0+, Java 17, Android SDK 35.

## Виджеты

- **Компактный 2×2** — доступность выбранных outbound (например, 2/3), до двух строк с задержками и статусом, опционально трафик inbound.
- **Расширенный 4×4** — до трёх выбранных outbound, время последней проверки, график и сводка inbound.
- **Адаптивное изменение размера**: если компактный виджет растянут по вертикали, он переключается на расширенный макет; при уменьшении возвращается к компактному.
- **Настройки у каждого виджета отдельно**: сервер, inbound, outbound, тип графика, outbound для графика, интервал агрегации 30/120/300 секунд, показ времени проверки и трафика.
- **Типы графика**: задержка выбранного outbound (мс), доступность на основе результата проб, усреднённая скорость изменения счётчиков inbound. Графики отрисовывает Android Canvas без WebView.
- **Кнопки**: ↻ принудительное обновление, ⚙ индивидуальная конфигурация.

## Экран приложения

«Обзор» включает суммарный статус Observatory, доступность и задержку выбранных outbound, историю задержек выбранного outbound, сводку и график inbound.

«Настройки» включают несколько HTTPS-панелей и токены, фильтры inbound и Observatory, агрегацию истории и интервалы обновления, уведомления и тему.

## API

- `GET /panel/api/server/xrayObservatory` — статусы и задержки outbound.
- `GET /panel/api/server/xrayObservatoryHistory/:tag/:bucket` — график задержек; при отсутствии endpoint сохраняются локальные пробы.
- `GET /panel/api/inbounds/list/slim` — inbound и счётчики; `/list` используется только при 404 и данные клиентов немедленно удаляются из ответа.
- Работает с read-only правами соответствующих методов API. Доступ `monitor` покрывает Observatory, но может не покрывать inbound в вашей версии панели. Не используйте административный токен без необходимости.

## История и ограничения

История задержки запрашивается только для выбранных элементов и ограничена четырьмя тегами на один период обновления. Исторические точки получаются с сервера, поэтому после первого успешного обращения график может появиться сразу. При отсутствии API ведётся локальная история. Фоновый Android JobScheduler обновляет приблизительно каждые 15/30/60 минут; режим 30 секунд или 2 минуты — агрегация истории сервера, **а не частота фоновых запросов Android**.

При увеличении компактного виджета уже размещённый экземпляр должен перейти в расширенный вид после следующего изменения размера или обновления. Лаунчеры могут ограничивать минимальный размер или обновления.

Сохранённые токены остаются зашифрованными Android Keystore, настройки версий 1.0 и 1.1 сохраняются. Сторонний код React/CSS из 3x-ui не копируется; оформление воспроизводит тёмную палитру панели.

## Сборка

[GitHub Actions — Android APK](https://github.com/toha17171/3xui-observatory-android/actions/workflows/android.yml)

Последняя успешная сборка → Artifacts → `xui-observatory-debug-apk`.

Локально: JDK 21, Gradle 8.9, Android SDK 35, `gradle assembleDebug`.

## Обновления

При установке поверх v1.1 будет сохранён идентификатор приложения `dev.observatory.xui`. При совпадении подписи APK приложение обновляется без удаления данных. Прежде чем удалить приложение, сохраните данные своих подключений: токены Android Keystore не восстанавливаются после удаления.
